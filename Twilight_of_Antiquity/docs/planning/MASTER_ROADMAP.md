# 17. 통합 개발 순서 — 실제 SAECVAR 제작 우선순위

- 상태: **최종 기획 통합 v0.3**, 구현/완료 선언이 아님
- 2026-10-16 기준의 권장 선후관계
- [08 최상위 로드맵](ROADMAP_QA.md)과 함께 유지; 상세 기능 ID는 [14](../reference/TOOLCHAIN_FUNCTION_CATALOG.md), 참고 레포는 [15](../reference/REFERENCE_REPOSITORIES.md).

**현재:** M0 환경 기반 구현과 G0 최소 날짜 가능성 실증을 기록했다. M1 초기 초안은 존재하지만 사용자 요청으로 추가 개발을 중단했으며 완료 단계가 아니다. 현재 구현과 엔진 검증 상태는 [STATUS](STATUS.md), 실험 근거는 [M0/G0 보고서](../quality/M0_G0_REPORT.md)를 따른다. 이 로드맵의 완료 조건은 유지한다.

## 1. 변경된 최우선 원칙

**분석기 전체를 완성한 뒤 모드 제작을 시작하지 않는다.** 또한 **사람용 완전한 GUI가 끝나야 Codex가 모딩을 시작할 수 있는 구조도 피한다.**

가장 먼저 안정적인 **읽기/정적 검증 기반(M0~M3)**을 만들고, **안전한 쓰기 API(M4)**가 생기면 즉시 **작은 고대 경제 수직 슬라이스(M5)**를 만들어 분석기와 편집기가 실제로 쓸모 있는지 확인한다. 이후 사람용 편집기와 고급 기능을 확장한다.

## 2. 개발 의존성 그래프

```text
M0 환경·데이터 소유권·현재 게임 버전 고정
  ├─ [G0] 600년 시작/720년 종료 '위험 조기 실증'(소규모 엔진 실행)
  ↓
M1 PDX Lexer/Parser + Fixtures
  ↓
M2 모드 로드/오버레이 + provenance
  ↓
M3 Symbol/Scope/정적 검증 + CLI JSON
  ↓
M4 공통 EditPlan + Source-preserving write + 안전한 Apply/Undo
  ↓
M5 Codex 사용 가능 편집 API + 소형 고대 경제 수직 슬라이스
  ├────────────→ M6 역사/경제 데이터 생성·빌드·검증
  └────────────→ M7 Human GUI 기본형(폼/검색/오류/차이)
                          ↓
M8 지도/이벤트/기술트리/게임 GUI/에셋 고급 편집
  ↓
M9 증분 분석·Codex 자동화·성능·회귀
  ↓
M10 세계 600년 데이터·120년 밸런스·출시
```

**M6와 M7은 M5 이후 서로 일부 병렬로 진행 가능**하지만, 동시에 같은 데이터·파일을 수정하지 않도록 M4의 트랜잭션/리비전 제어를 전제한다. M9의 필수 최소 회귀와 코드 검사는 M1부터 존재한다. 뒤로 표시한 것은 고도화 단계다.

## 4. 시작 즉시 수행할 G0 위험 실증

날짜 변경이 아예 불가능하거나 120년간 달력이 정상 처리되지 않는다면 전체 개발 구상이 흔들릴 수 있다. 그러므로 **Rust 툴체인의 고급 기능 완성 전에** 작은 샘플 모드를 별도로 사용해 다음을 확인한다.

1. 목표 게임 버전·설치 DLC/모드 환경 기록.
2. 최소 모드 인식·활성화.
3. 서기 600년 시작과 날짜 진행, 세이브·로드.
4. 720년 종료 또는 자유 진행의 정확한 동작.
5. 실패 시 대안(시뮬레이션 날짜를 다른 기년법으로 표시하는 등)을 검토하되 **채택 여부는 별도 의사결정**.

사용자 목표인 '가능하면 게임 실행은 GUI 확인 때만'을 존중하되, G0 및 이후 실제 AI·경제·군사 테스트는 게임 실행이 필요하다. **확인된 공식 무GUI 전용 검증 명령이 없는 상태에서 이를 있다고 단정하지 않는다.**

## 5. M0~M5 구체 작업 순서 (처음 Codex 개발 사이클)

**작업 01** 게임 경로·버전 및 읽기 전용 원본 입력 정의 → **작업 02** 최소 날짜/모드 G0 실험 → **작업 03** 테스트 Fixture와 확정 문법/미지원 문법 목록 → **작업 04** Parser/CST/오류 위치 → **작업 05** mod overlay + provenance → **작업 06** symbol/ref/Scope + JSON diagnostics → **작업 07** 변경 미리보기/트랜잭션/Rename → **작업 08** goods/buildings/pops typed authoring → **작업 09** 작은 고대 경제(국가 2~3, 상품 5개 안팎) → **작업 10** 정적 통과 + 최소 게임 실행 증거.

M5 도달 전에는 전체 600년 국가의 역사 데이터 대량 제작, 거대한 UI, 완전한 국가 목록을 작업의 선행조건으로 만들지 않는다.

## 6. 최소 사용 가능한 도구와 결과

- **Codex-first MVP:** `inspect`, `check`, `preview`, `edit`, `apply`, `rollback`이 가능한 JSON 기반 CLI + 구조적 변경 API.
- **Human MVP:** 같은 데이터를 조회·편집하는 폼/테이블과 코드·진단·변경 승인 UI.
- **고급 사용자 도구:** 지도·국기·이벤트 그래프, 기술트리, GUI canvas, 테스트 대시보드.
- 실제 CLI 옵션·명령 이름은 [13 검사 계약](../architecture/ANALYZER_RULES_REPORTS.md)의 설계 예제와 별개로 코딩 단계에서 안정화한다.

## 7. 실패·중단·재개 기준

- 고정된 게임 버전에서 고위험 날짜 동작이 실패하면 다른 기능을 무작정 늘리기 전에 설계 결정을 다시 한다.
- Parser가 원본을 손실시키면 안전한 쓰기부터 구현하지 않고 CST 오류를 수정한다.
- Overlay가 불확실하면 정적 예측 신뢰도를 낮추며 런타임 검증으로 분류한다.
- 자료 출처가 부족한 정치체는 보수적 데이터/불확실성 표시를 사용한다.
- M4가 Source-Preserving/transaction을 통과하지 못하면 다국가 일괄 쓰기를 허용하지 않는다.
- M5 경제 루프가 정상 작동하지 않으면 세계 확장을 중단하고 핵심 시스템을 수정한다.

## 8. 각 단계 완료 정의(DoD)

매 단계는 **실행 가능한 샘플 + 자동 검사 + 인공 오류 fixture + 문서/결정 기록 + 되돌림 가능성 + 두 차례 연속 리뷰에서 수정 사항 없음**을 완료 조건으로 한다. 날짜/경제/GUI 같은 런타임 의존 단계는 **실제 게임 증거**가 없으면 완료 처리하지 않는다.

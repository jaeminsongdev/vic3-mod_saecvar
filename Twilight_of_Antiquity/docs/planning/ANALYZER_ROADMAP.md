# 12. SAECVAR Analyzer 자체 구현 로드맵

- 상태: **개발 계획** / 구현 마일스톤 미완료
- 원칙: Tiger를 필수 개발 도구로 사용하지 않음. 코드·검증 엔진은 독립 구현.
- **v0.3 관계:** 이 문서는 **Analyzer 하위 단계(A0~A7)** 명세다. 전체 M0~M10의 공식 선후관계는 [17 통합 로드맵](MASTER_ROADMAP.md)이 우선한다. 아래 A5/A6/A7의 고급 기능을 모두 끝내기 전에 M4 안전 편집과 M5 고대 경제 수직 슬라이스를 시작하도록 권장한다.
- 관련: [08 통합 로드맵](ROADMAP_QA.md) · [11 아키텍처](../architecture/ANALYZER_ARCHITECTURE.md) · [13 규칙·출력](../architecture/ANALYZER_RULES_REPORTS.md)

## 1. 선후 관계

```text
A0 기초·버전·입력 정책
  ↓
A1 Lexer/CST/Parser + 오류 복구
  ↓
A2 로드 순서 + Mod Overlay/객체 적용
  ↓
A3 심볼·참조·타입·Scope
  ↓
A4 JSON 진단/CLI 안정화 + 테스트/CI
  ├──→ [M4] 공통 EditPlan·트랜잭션·Typed API
  │       ↓
  │    [M5] 작은 고대 경제 수직 슬라이스 + 엔진 증거
  └──→ A5 역사·경제·기술 전문 규칙(병행)
          ↓
       A6 의존성 그래프/증분 분석 + Codex 워크플로(고도화)
          ↓
       A7 게임 엔진과의 정적 예측 차이 검증/보정(지속)
  ↓
[M6~M10] 전 세계 역사 데이터·GUI·릴리스
```

**고위험 조기 검증:** 600년 시작·720년 종료 가능성은 **A1~A4의 최소 환경을 확보한 시점**부터 별도 소규모 엔진 테스트로 병행한다. 분석기 완성까지 미뤘다가 날짜 처리 한계가 나오는 상황을 피한다.

## A0. 개발환경·코퍼스·도구 기준 확립

**해야 할 일**
- Rust workspace 초기화(언어는 현재 권장안), CI에서 수행할 순수 fixtures와 로컬 게임 설치 입력 분리.
- `game_root`, `dlc_roots`, `mod_roots`, `load_order`, `game_version`, `ruleset_version` 설정 계약 정의.
- 원본 게임 파일은 읽기 전용. 라이선스가 허용되지 않는 게임 자산은 배포하지 않는다.
- 참고 구현(Tiger/Jomini)을 실행 의존성으로 추가하지 않는다.
- 규칙/파일 기반 회귀·성능 테스트, 검사 상태 분류를 미리 확정한다.

**통과 조건:** 설정과 인공 fixtures를 입력받아 결정적 결과를 생성하는 CLI 최소 골격.

## A1. 독립 Parser MVP

**해야 할 일**
- Tokenizer: `{ }`, 연산자, 문자열, 값, 주석, 공백·위치 처리.
- 순서·중복키·주석·원본 범위를 보존하는 CST.
- 의미 분석용 AST와 오류가 있어도 가능한 부분을 복구하는 parser.
- 게임 원본 예제와 자체 fixture를 분리하고 파싱 성공률 및 예외 목록 작성.
- property-based/fuzz 테스트, UTF 인코딩과 오류 메시지.

**통과 조건:** 정상 fixture는 정확한 트리, 오류 fixture는 파일·줄·열과 복구 진단. 파일 전체 분석 중단률을 측정할 수 있음.

**선행 검증 포인트:** parser 성공이 파일의 의미적 유효성이나 게임 로딩을 보장하지 않는다는 명시.

## A2. 파일/객체 적용 규칙 엔진

**해야 할 일**
- 원본/DLC/모드 입력 경로와 로드 순서를 별도로 모델링.
- 동일 경로 파일 덮어쓰기 vs 객체 정의 간 충돌/교체/추가를 구분.
- `INJECT:`, `REPLACE:` 및 확인된 variants의 파일 영역·적용 예외 분석.
- 각 정의의 기원·차단된 정의·로드 우선순위를 설명하는 `provenance` 트리.
- GUI·이벤트·로컬라이제이션·defines는 섞지 않고 별도 로드 규칙으로 분리.

**통과 조건:** golden fixture에서 최종 정의를 설명 가능하고, 미지원 규칙을 확정 성공으로 잘못 표시하지 않음.

## A3. Reference/Schema/Scope 분석

**해야 할 일**
- 국가·문화·종교·주·건물·상품·기술·정치·군사 데이터의 인덱스.
- 문서 및 버전별 원본 패턴을 바탕으로 스키마·Scope 등록부 구성.
- 객체 참조가 실제 최종 오버레이에 존재하는지 확인.
- 이벤트/효과/트리거 컨텍스트 검사.
- 중복 및 참조해결 충돌의 위치·영향 경로 출력.

**통과 조건:** 잘못된 ID/Scope fixtures에서 높은 탐지율, 정상 원본 fixture의 오탐 기록과 원인 설명.

## A4. 진단·CLI/CI 최소 완결

**해야 할 일**
- 표준 진단 JSON 규격 확정: 규칙 ID·심각도·신뢰 상태·파일 범위·원인·출처.
- 최소한 `check --full --format json` 및 `explain` 명령 구현.
- 검사 실패 정책: 지원된 규칙의 ERROR만 CI 실패, 경고/미지원은 명시적으로 분리(정책은 옵션 가능).
- 게임 원본이 필요한 전체 검사는 로컬/셀프호스팅에서 실행, 공용 GitHub Actions에는 공개 fixture만.
- Codex가 리포트 파일을 읽어 관련 파일만 수정하도록 도구 사용 규칙 문서화.

**통과 조건:** 파서·오버레이·참조 문제 3종 이상을 의도적으로 삽입해 감지, 재검사 후 해당 오류 해소 확인.

## A5. SAECVAR 특화 규칙

**해야 할 일**
- 600년 존재 국가·종교·기술 시대 제약(사료 신뢰도별 경고).
- 경제 상품 생산→소비/필수 투입 관계·기술 해금 그래프.
- 국가 소유·POP·법률 및 로컬라이제이션 간 연결.
- 날짜로 국가 멸망이 강제되는 로직 등 역사적 분기 원칙 위반 후보.
- 리포트의 확실성: `HIST`는 사료 등급과 추론을 함께 노출.

**통과 조건:** 확정 고증과 게임적 재구성을 혼동하지 않으면서 정적 구조적 결함을 탐지.

## A6. 증분 분석·통합

**해야 할 일**
- 변경 파일을 기준으로 재파싱하고 참조 그래프의 영향받는 객체를 재검증.
- 게임 패치·DLC·모드 로드 순서 변경에 대한 정확한 캐시 무효화.
- `check --changed`, SARIF/HTML 출력을 지원.
- Codex와의 자동 수정·재검증 시나리오 문서화(수정 파일 범위/횟수 가드 포함).

**통과 조건:** 증분/전체 분석 결과의 관련 진단 일치, 동일 입력에 대한 출력 결정성.

## A7. 실제 엔진과 차이 비교

**해야 할 일**
- 별도 실험용 작은 모드에서 실제 게임 로딩·스크립트 오류·객체 반영 결과와 정적 모델 비교.
- 오탐·미탐·미지원 문법 및 로드 순서 예외를 회귀 fixture로 환류.
- 600년 시작·720년 종료·세이브/로드·경제/전투/AI의 실행 검증 기록.

**통과 조건:** 확인한 게임 버전의 주요 경계 사례에 대한 오탐·미탐 추적, 엔진 실험과 정적 검사 결과의 불일치 목록이 문서화됨. **게임 실행 자체를 없애겠다는 목표는 아님.**

## 2. 개발 단계별 검토 자료

| 단계 | 주요 결과 | 자동 테스트 | 수동/엔진 확인 |
|---|---|---|---|
| A1 | CST/AST/구문 오류 | fixtures, fuzz | 문법 예외 검토 |
| A2 | 최종 적용 예측 | golden overlays | 규칙 불일치 사례 |
| A3 | 참조·Scope | 유효/무효 참조 fixtures | 스키마 버전 검토 |
| A4 | CLI JSON | 스냅샷/종료 코드 | Codex 재검사 |
| A5 | 역사·경제 룰 | 추정/확정 사례 | 사료 검토 |
| A6 | 증분 캐시·SARIF | 전체 vs 증분 | 실제 워크플로 |
| A7 | 엔진 비교 | 회귀 자동화 | 최소 실제 게임 실행 |

## 3. 1차 구현에서 의도적으로 제외

- 자체 엔진을 이용한 AI 경제 시뮬레이션 또는 자동 게임 플레이 재현.
- 복잡한 자동 코드 수정/리팩터링 전용 IDE.
- 모든 Paradox 게임 포맷의 동시 지원.
- 미지원 GUI 및 바이너리 데이터 포맷을 '검증 성공'으로 간주.
- 범용 분산 실행/클라우드 대시보드부터 만들기.

## 4. '완성' 보고 규칙

규칙 단위로 정상·오류·거짓양성/거짓음성·미지원 샘플을 기록하고 **2회 연속 검토에서 수정할 항목이 없을 때** 해당 단계의 문서/정적 검사 구현을 완료로 보고한다. 엔진 연동 단계는 엔진 증거가 없으면 완료로 보고하지 않는다.

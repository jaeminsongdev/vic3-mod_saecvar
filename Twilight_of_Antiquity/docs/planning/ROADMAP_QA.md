# 08. SAECVAR 전체 개발 로드맵 — 우선순위 기준

- 상태: **v0.3 통합 로드맵** (실제 코드 개발은 아직 시작되지 않음)
- **이 문서는 전체 개발의 최상위 목차**이며 [17 통합 마일스톤 상세](MASTER_ROADMAP.md)가 유일한 M0~M10 공식 일정·선행관계 명세다.
- 분석기 내부 하위 단계는 [12 Analyzer 로드맵](ANALYZER_ROADMAP.md)에, 전체 기능은 [14 기능 카탈로그](../reference/TOOLCHAIN_FUNCTION_CATALOG.md)에 기술한다.
- 기술적 핵심: **Tiger 참고 전용 + 자체 정적 분석기 + 공통 편집 코어 + Codex/Human 동등한 클라이언트**.

## 1. 가장 먼저 할 일과 그 이유

'전 세계 600년 지도 제작'도 'GUI 대형 편집기'도 첫 단계가 아니다.

1. 설치 게임 버전·DLC·데이터 소유권을 결정하고 기존 원본은 읽기 전용으로 보관.
2. **G0: 날짜/시작/종료 가능성 소규모 엔진 위험 실증**을 매우 이른 시기에 수행해 프로젝트를 뒤늦게 뒤엎는 상황 방지.
3. 파서 → 모드 적용 해석 → 심볼·Scope·진단의 **최소 독립 Analyzer** 개발.
4. Codex와 GUI가 공유할 **typed EditPlan·트랜잭션·source-preserving write** 구현.
5. **고대 경제 최소 수직 슬라이스**로 실제 모드 제작과 도구를 함께 검증.
6. 그 뒤 역사 데이터 자동 생성, 기본 사람용 편집기, 지도·이벤트·게임 GUI 제작 지원, 글로벌 확장.

## 2. 최상위 M0~M10

| 단계 | 목표 | 산출물/게이트 |
|---|---|---|
| **M0** | Workspace·타깃 게임버전·데이터 원본 정책 | 신뢰 가능한 입력 스냅샷, 합법적인 fixture 및 작업 기반 |
| **G0** | 600~720년 엔진 위험 조기 확인 | 실제 게임의 시작/날짜/세이브·종료 동작 증거 |
| **M1** | 독립 PDX Parser/CST | 위치·주석 보존 및 오류 복구 테스트 |
| **M2** | 로드 순서와 정의별 Overlay | 최종 정의·provenance 출력 |
| **M3** | Semantic/Schema/Scope·JSON CLI | 참조·정적 오류 검사 |
| **M4** | 공통 구조적 편집기·트랜잭션 | Preview → Validate → Apply → Rollback |
| **M5** | 첫 작은 고대 경제 모드 | Codex typed API로 상품·건물·POP 수정 및 엔진 검증 |
| **M6** | 역사·경제 데이터 파이프라인 | 출처 데이터 → PDX 생성, 버전·해시 재현 |
| **M7** | Human Workbench MVP | 동일 API의 폼·검색·오류·변경 승인 |
| **M8** | 지도·기술·이벤트·GUI·에셋 | 고급 비주얼 편집과 엔진 호환성 검사 |
| **M9** | 증분·자동화·회귀·실행 증거 | Codex 자동 재검사, 성능, 실제 로그 대조 |
| **M10** | 전 세계 콘텐츠·장기 밸런싱·배포 | 600~720년 주요 국가·경제·AI·UI 안정성 |

**M6와 M7은 M5 이후 일부 병렬 진행 가능.** 각 단계의 테스트는 후속 단계에서도 계속된다. M9의 정적 검사 고도화를 끝내야 모드 개발을 할 수 있다는 뜻은 아니다.

## 3. 필수 품질 게이트

- **문법/정의/Overlay 검사:** 게임 없이 자체 Analyzer에서 검사하되 미지원/추정 상태를 남김.
- **편집 안전성:** 예상 파일 목록·semantic diff와 충돌 검사·롤백을 완료한 뒤만 자동 쓰기 허용.
- **실제 엔진:** 서기 600년 시작·720년 처리·경제·AI·전투·세이브는 실제 게임 동작 증거 필요.
- **역사자료:** 추정된 경계·인구·종교는 사료 신뢰도를 표시하며 자동 생성이 사실의 증명은 아님.
- **릴리스:** 재현 가능한 빌드, 한국어/영어 등 지원언어 정책, 원본 게임 데이터 무단 배포 방지.

## 4. Codex와 사람용 기능 통합

기획상 공통 기능 56개, Codex 특화 14개, 사람 특화 16개, 횡단 원칙 10개를 관리한다(추적 ID 96개). 자세한 도메인/기능/참고 레포/우선 단계는 [14 기능 카탈로그](../reference/TOOLCHAIN_FUNCTION_CATALOG.md)에 각각 있다.

Codex와 Human은 **같은 정의·같은 검증·같은 파일 변경 엔진**을 사용한다. 별도의 서로 다른 parser/DB/validator로 이중 개발하지 않는다. [16 아키텍처](../architecture/TOOLCHAIN_ARCHITECTURE.md), [18 작업 계약](../architecture/SHARED_WORKFLOWS.md) 참고.

## 5. 완료 보고 규칙

- 각 작업은 정상·오류 Fixture, 증분/전체 비교 가능한 테스트, 코드/데이터 변경 근거를 갖는다.
- 분석 결과를 실제 게임 적용 성공이라고 잘못 주장하지 않는다.
- 버전별 게임 규칙 불확실성을 명시한다.
- **2회 연속 검토에서 추가 수정 사항이 없고, 해당 단계의 실행/정적 증거가 충분할 때만 작업 완료**로 보고한다.
- 이번 v0.3 업데이트는 **문서 변경**이며 Rust/GUI 구현 완료가 아니다.

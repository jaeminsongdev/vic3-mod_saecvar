# 07. 군사·지도·게임 데이터 설계

- 상태: 지구를 배경으로 한다는 점은 **확정**, 지도 수정 방식·군사 편제는 **미확정 설계**
- 주요 제약: 빅토리아 3의 전쟁·전선·해전 엔진을 전략 전술게임으로 교체할 수 있다고 가정하지 않음

## 1. 지도에 관한 기본 방향

기존에 검토한 '새 행성·새 대륙' 구상은 폐기하고, **지구의 실제 지형을 사용**한다. 우선 원작 지도 기반으로 정치 경계·주 데이터·지역 인구와 경제를 고대화하는 접근을 **개발상 권장안**으로 둔다.

현재 미확정:
- 완전한 새 프로빈스 지도 제작 여부.
- 특정 지역의 주·프로빈스 세분화 범위.
- 600년의 정확한 지형·도시·항구 로케이터를 어디까지 수정할지.
- 국가별 정치영역을 표현할 최소 단위와 지도 성능 상한.

## 2. 600년 지도 데이터의 단위

시작 시 반드시 분리해야 할 데이터:
- **고정 지형:** 육지·바다·강·산악·도서, 통행·항로.
- **주/프로빈스:** 게임 엔진의 행정·군사·경제 구획.
- **정치 소유권:** 600년 당시 정치체·지배권과 영향권의 구별.
- **문화·종교·인구:** 정치적 국경과 별개의 분포.
- **경제:** 지역 특산물·기반 생산·교역과 이동 접근성.
- **역사적 불확실성:** 정확한 국경/지배권이 불분명한 경우 명시적 추정.

현대 국가 국경을 고대국가 국경으로 기계적으로 대체하는 것을 피한다. 유목 정치체·도시국가·느슨한 연맹은 원작의 면적 중심 영토 표시 방식과 어긋날 수 있으므로 추상화 방식을 별도 설계한다.

## 3. 군사 개편 방향

| 분야 | 표현하고 싶은 역사 요소 | 엔진에서의 우선 표현 |
|---|---|---|
| 병력 동원 | 군역·상비 병력·지역세력 동원 | 병영·병종 데이터·모집/유지비·법률 효과 |
| 병종 | 보병·궁수·기병·중기병 등 | 부대 종류·생산방식·전투 통계(지원 범위 검증) |
| 공성·방어 | 성곽·장기 공성·국경 요새 | 전투 보정·방어 비용·주 효과의 추상화 |
| 군수 | 곡물·장비·말·운송·보급 비용 | 상품 투입·유지비·경로·지역 인프라 |
| 해상 활동 | 연안 항해·수송·해군 동원 | 해군 편제·선박 관련 생산·해역 접근 |

병종 이름만 개조하는 것으로 전술전투를 재현했다고 보지 않는다. 군대의 이동·전선 형성·공성·전투 절차에서 **하드코딩된 부분은 그대로 남을 수 있다.**

## 4. 해상·육상 교통과 국제 연결

- 현실적으로 존재한 해역·연안·교역로를 고려.
- 아라비아·인도양·홍해·지중해·중앙아시아 등의 교역 연결은 국가 관계와 물류에 반영 가능성 검토.
- 600년 당시 유라시아와 아메리카를 서로 자유롭게 무역하는 단일 시장으로 연결하지 않는다.
- 원작의 배 이동 및 시장 접근성 모델로 고대 운송과 교역을 얼마나 구현할 수 있는지 테스트.
- 장거리 항해와 전투능력을 단순 국력 점수에 비례시켜 자동 부여하지 않는다.

## 5. 프로토타입 지도 추천

새 대륙을 만들기보다 먼저 현재 세계지도 위에서:
1. 600년 기준 정치체 2~3개와 인접 주를 작은 지역에 구성.
2. 농업 생산·병력·국경·전선·평화 후 국경 변화를 테스트.
3. 연안 항구·해군 또는 육로 교역을 하나씩 연결.
4. 동일 구조를 원거리 지역에 확대했을 때 엔진·AI 제약 비교.

다음 단계에서 세계 전체에 대한 기초 역사 데이터를 입력한다. 일부 지역의 상세 국경이 미확정이라도 전체 지도 범위 자체는 세계로 유지한다.

## 6. 데이터·호환성 규칙

- 모드 메타데이터와 목표 게임 버전을 명시한다.
- 국가, 문화, 종교, 주, 자원, POP, 기술, 이벤트의 안정된 ID와 이름 규칙은 프로토타입 후 확정한다.
- 원작 파일 경로나 문법을 기억에 의존하여 작성하지 않고 **설치된 게임 버전과 현재 모딩 문서로 확인**한다.
- 병종·로케이터·지도 이동·AI에 대한 검증을 각각 분리한다.
- 기존 원작에 새 DLC/패치가 출시되면 데이터 덮어쓰기·충돌 영향을 회귀 테스트한다.

## 7. 게임 원본·DLC·모드 오버레이 정적 해석

자체 분석기는 입력 루트(원본 게임·설치된 DLC·활성 모드)를 수집하고, **파일 경로 교체**와 **객체 수준 정의 덮어쓰기/INJECT/REPLACE 등**을 구분하는 버전별 규칙으로 최종 데이터 집합을 모델링할 계획이다.

- 객체 종류·폴더·로드 순서에 따른 차이를 일률적인 '나중 것이 항상 우선'으로 처리하지 않는다.
- 모드에서 기대한 건물·주·전쟁 관련 정의가 원본에 의해 예상치 않게 무효화될 때 출처와 이유를 제시한다.
- 미지원 파일 형식, 복수 모드간 예외, GUI/로컬라이제이션의 특수 규칙은 불확실성으로 표시한다.
- 사용자가 설치한 유료 게임·DLC 파일은 **로컬 읽기 전용 입력**으로 관리하고 공개 저장소와 CI 아티팩트에 복사하지 않는다.
- 전투 성패·육해군 이동·지도 렌더링·해상 항로의 실제 동작은 정적 구조 확인만으로 검증할 수 없다.

- 상태: **개발 계획**. 아래 어느 구현 마일스톤도 완료된 것으로 표시하지 않는다.

## 0. 우선순위 결정

개발 도구는 Tiger 등의 검증 실행 파일에 의존하지 않는 **자체 SAECVAR Analyzer**로 구현한다. 반복적인 모드 코드 검사에서는 게임 실행 없이 문법·참조·로드 규칙·데이터 일관성을 검사하고, 실제 엔진 실행은 핵심 호환성·통합 시뮬레이션·GUI 확인을 위해 별도로 사용한다.

**실행과 정적 검사를 혼동하지 않는다.** 자체 분석기의 '정적 통과'는 Victoria 3 런타임 성공을 보장하지 않으며, 공식 무GUI/헤드리스 검증기 존재를 전제로 하지 않는다.

| 우선순위 | 마일스톤 | 선행 조건 | 핵심 산출물 |
|---|---|---|---|
| **P0-0** | 개발 기초·입력자료 정책 | 없음 | Rust 작업공간 계획, 게임 버전·입력 루트·테스트 기준 |
| **P0-1** | 독립 PDX Lexer·Parser | P0-0 | 위치 추적 CST/AST, 오류 복구, 구문 검사 |
| **P0-2** | 원본+DLC+모드 해석기 | P0-1 | 로드 순서·교체·객체 병합의 정적 모델 |
| **P0-3** | 심볼·참조·의미 분석 | P0-2 | 인덱스·검사기·버전별 스키마 |
| **P0-4** | 진단 엔진·CLI·기초 회귀테스트 | P0-1~3 | JSON/SARIF/HTML 계획 중 우선 JSON, CI용 실패 코드 |
| **P0-5** | SAECVAR 전용 검사·증분 분석 | P0-4 | 역사·경제 규칙, 캐시·의존성 그래프 |
| **P1** | 최소 엔진 호환성 실증 | 정적 베이스라인; 필요하면 조기 병행 | 600년·720년·세이브·로드의 실험 결과 |
| **P2** | 고대 경제 수직 슬라이스 | P1, P0-4 | 상품·건물·POP·기술 최소 루프 |
| **P3** | 국가·정치·군사 수직 슬라이스 | P2 | 법률·행정·외교·전쟁 최소 운영 |
| **P4** | 600~720년 장기 시뮬레이션 | P3 | 기술·경제·AI·성능 검증 |
| **P5** | 전 세계 600년 역사 데이터 | P4의 핵심 병목 해소 | 글로벌 국가·문화·종교·경제 초기값 |
| **P6** | 분기 콘텐츠·밸런스·릴리스 | P5 | 역사적 선택지, QA, 로컬라이제이션 |

**의존성 주의:** P1은 고위험 날짜·로드 조건에 대한 **최소 실험**이므로 P0-5 전체 완료까지 의도적으로 지연시킬 필요는 없다. P0-1~4의 작은 유효한 입력을 확보한 즉시 소규모 엔진 실증을 병행할 수 있다.

## P0: 분석기 선행 구현

자세한 하위 과제와 Definition of Done은 [12](12_ANALYZER_ROADMAP.md)에 있다.

### P0-0 — 개발 기반
- Rust CLI/라이브러리 모듈 계획, 기본 테스트/로그 구조, 로컬 게임 경로 설정.
- 게임 버전·DLC·활성 모드 목록을 읽기 전용으로 관리하고 버전·파일 해시 기록.
- Tiger와 Jomini의 소스/문서는 **참고자료**, 직접 코드 재사용은 **별도 라이선스 심사**.

**통과:** 순수 fixture 파일을 받아 유효한 기초 진단 리포트를 출력하는 빈 틀 동작.

### P0-1 — PDX 구문
- 주석, 중첩 블록, 중복 키, 비교 연산자, 문자열, 소스 위치 보존.
- 오류 복구, 정상·오류 fixtures, 속성·퍼징 테스트.
- 원본 텍스트가 없어진 '추상 파싱'이 아니라 검사 위치를 재현할 수 있는 구문 모델.

**통과:** 선정한 게임 원본 텍스트 코퍼스와 오류 샘플을 재현 가능하게 분석. 미지원 구문은 누락 없이 별도 보고.

### P0-2 — 모드 적용 모델
- 파일 오버레이, 게임별 로드 순서, 객체 병합/교체·추가, GUI·이벤트·로컬라이제이션 예외 분리.
- 모든 최종 정의에 provenance(기여 원본·모드 파일·행)를 연결.
- 게임 버전별 모델 스냅샷과 정답 golden fixtures 구성.

**통과:** 사용자가 지정한 객체의 최종 적용 예측 및 근거 추적 가능. 모호하면 판정 보류.

### P0-3 — 의미·참조
- 국가·건물·상품·기술·법률·문화 등 심볼 테이블.
- 미존재 참조, 중복 정의, 타입·Scope, 로컬라이제이션 연결.
- 버전별 합법 키·Scope를 알 수 없으면 보수적으로 경고하거나 미지원 판정.

**통과:** 잘못된 참조를 주입한 fixtures에서 재현성 있게 발견하고 정상 샘플에 대한 오탐 기록.

### P0-4 — 사용 가능한 CLI 검사
- 최소 명령: `check --full`, `check --changed`(후기 단계에서 최적화), `explain <rule-id>`.
- JSON 우선 안정화 후 SARIF 및 HTML 출력 확대.
- 진단에 정확한 파일·줄·열·규칙·설명·확실도·근거 포함.

**통과:** Codex가 파일을 수정한 후 JSON 결과를 받아 다시 수정·재검사할 수 있음. 단 자동 수정 자체는 별도 기능이며 위험한 자동 패치는 금지.

### P0-5 — 특화 검사와 성능
- 600년 역사 데이터, 경제 상품 생산·소비, 기술 해금 그래프, 적용 안 되는 정의 등을 분석.
- 의존성 그래프 및 증분 캐시.
- 원본+DLC+모드 구성에 대한 오탐/미탐·성능 회귀 평가.

**통과:** 작은 유효 모드 fixture의 변경→검사 반복이 신뢰 가능하며, 전체 검사와 증분 검사의 결과가 일치.

## P1 — 최소 실제 엔진 검증 (별도 관문)

목표: 600~720년 캠페인의 **기술적 선결 조건**을 확인.

- 실제 설치 버전에서 빈 모드 로드, 서기 600년 시작, 날짜 진행, 720년 범위 처리.
- 세이브/로드와 중요 경제·군사 상태가 엔진에서 유지되는지.
- 가능한 경우 엔진 로그·스크린샷·재현 단계를 기록하고 정적 분석 결과와 차이를 비교.
- 특정 무GUI 실행 옵션·디버그 모드 무사용 로깅을 **이미 지원되는 기능으로 단정하지 않음**.

**통과:** 해당 게임 버전과 설치 조합에 대한 실험 증거 확보. 엔진 날짜 처리가 불가능하면 구현 범위·대안에 대한 재설계 결정부터 진행한다.

## P2~P4 — 실제 모드 수직 슬라이스

**P2 고대 경제:** 농업·상품·수공업·POP·기술·군사 물자 등 핵심 루프를 작은 지역에 연결. 정적 오류 0건을 통과한 변경만 엔진 통합 검증으로 넘긴다.

**P3 국가 운영:** 정치·법률·지역 통치·외교·전쟁을 두 개 이상의 대비되는 국가에 연결. 전투 시스템의 하드코딩된 한계를 반영한다.

**P4 장기 플레이:** 600~720년의 경제 성장·AI 의사결정·세이브·성능을 측정하고, 빈약한 후반 콘텐츠·무한 성장·파산 패턴을 교정한다.

모든 단계의 엔진 작동 여부는 분석기 결과와 별도 증거로 기록한다.

## P5~P6 — 글로벌 확장과 정식 공개

- 전 세계 600년 정치·인구·경제·종교·문화 데이터의 사료 고증 및 신뢰도 기록.
- 지역별 기본 플레이 가능성과 게임 규모에 대한 성능 회귀.
- 고대 말기 역사 사건은 날짜 고정 결말이 아니라 게임 상태 조건을 갖춘 분기로 구현.
- UI·텍스트·로컬라이제이션·배포·라이선스 점검.
- 이후 다른 SAECVAR 시리즈가 생기면 분석기 범용 재사용 여부를 별도 평가.

## 품질 게이트: 어떤 검사가 어디에 필요한가

| 검사 | 게임 실행 | 완료 증거 |
|---|---|---|
| 파서·정의·참조·스키마 | 불필요 | JSON/SARIF 진단, 버전·규칙 식별 |
| 모드 적용 결과 예측 | 불필요 | 정의 provenance, 신뢰도·근거 |
| 600년 역사·경제 구조 규칙 | 불필요 | 규칙별 근거와 예외 표시 |
| 실제 엔진 로드·AI·전투·세이브 | 필요 | 게임 로그·세이브·시뮬레이션 결과 |
| GUI·지도·텍스트 렌더링 | 필요 | 스크린샷 및 수동 확인 |

## 문서·구현 완료 판정

- 신규 검증 규칙에는 성공/실패/오탐/미지원 fixture를 둔다.
- 원본 게임·DLC 파일의 무단 배포를 피한다.
- 동일 파일에서 분석 결과가 결정적으로 재현되어야 한다.
- 스키마·규칙 변경 후 전체 및 증분 검사 결과를 비교한다.
- **연속 2회 검토에서 추가 수정 필요 사항이 없는 경우에만 문서/해당 마일스톤 완료로 보고**하며, 실제 개발·실행은 따로 증명한다.

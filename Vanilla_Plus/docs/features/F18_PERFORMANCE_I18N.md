## 횡단 요구사항

- **사용자 제어:** 자동화 허용 범위는 국가·주·건물 유형·업종별 제외 목록과 최대 예약/실행 주기를 가진다. 게임 내에서 실제 제공할 수 있는 설정 UI 방식은 별도로 검증한다.
- **원본 제약:** 법률·기술·예산·시장접근·외교 자원·건설력 등의 제한을 우회하지 않는다.
- **비대칭 방지:** 수치 보정은 양 진영/AI에 일관되게 적용하는 것을 원칙으로 하되, 게임 스크립트로 가능한지 검증한다.
- **정보 표시 원칙:** 계산된 예측값과 게임에서 읽은 실제값을 별도 레이블로 표시한다.
- **오류 격리:** 한 모듈의 결함이 다른 모듈 UI·밸런스에 연쇄 영향을 미치지 않게 의존도를 제한한다.
- **호환성:** 저장 데이터, 로컬라이제이션 키 충돌, GUI 전체 파일 대체, 도전과제·멀티플레이 호환성을 개별 검증한다.
- **후반 성능:** 매일 세계 모든 주를 검사하는 방식보다 주기적 검사·플레이어 선택 조건·메모이제이션 가능성을 우선 검토한다.

## 실행 설계(엔진 지원 여부는 Q0에서 검증)

- **선행:** F04/F05/F06. 독립 시리즈 Twilight의 미완성 M1을 전제로 하지 않는다.
- **입력:** UI·스크립트 처리량·언어·수치 단위·화면 배율.
- **판단:** 후반 세이브 성능·한국어/영어 표기·단축키 계측.
- **안전 경계:** 문화/종교 강제 단일화 같은 의미 변경 금지.
- **처리 순서:** 데이터 관측 → 실제 엔진 기능·법률·기술 조건 확인 → 예상 비용/영향 계산 → 근거 표시 → 사용자 승인 → 실행 직전 상태 재검증 → 정상 게임 액션 실행/불가사유 표시.
- **결과 객체(개념 설계):** `FeatureDecision { id, game_build, subject, observed_at, feasibility, evidence, estimated_effects, permitted, reasons, proposed_action }`. 실제 게임 API라고 주장하지 않는다.
- **중단/실패 복구:** 지원하지 않는 상태·데이터 부재·버전 불일치·다른 모드 충돌이면 **실행하지 않으며**, 무엇이 불가능한지 화면/로그에 남기도록 설계.

- **대표 정상/오류/경계:** 대국 후반 틱·한국어 억단위·글꼴/스크롤.
- **정적 게이트:** 변경된 파일의 구문·참조·로컬라이제이션·동일 GUI/defines 경로 충돌·대상 게임 빌드 차이 검사.

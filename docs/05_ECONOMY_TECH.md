# 05. 고대 경제·생산·기술 시스템

- 상태: **전면 고대화 방향은 확정**, 세부 상품·건물·기술트리와 수치는 설계 제안
- 관련: [기술 검증](10_VALIDATION.md), [군사와 지도](07_WAR_MAP_DATA.md)

## 1. 개편 목표와 엔진 제약

빅토리아 3는 생산요소·상품가격·임금·국가재정 등 산업시대 시장경제를 중심으로 시뮬레이션한다. 이를 7세기 고대경제로 그대로 이식할 수 없으므로 **'고대의 생산·잉여·지대·조세·교역'을 원작 메커니즘으로 추상화**해야 한다.

다음 중 특정한 구현을 이미 지원한다고 단정하지 않는다.
- 현물 징수와 부역의 정확한 법적·경제적 모델.
- 노동·임금·가격 자체를 제거한 경제 엔진 대체.
- 별도의 고대 조세 장부, 도로·공납·물류 알고리즘.

우선 구현 가능한 데이터 정의(상품·건물·생산방식·수요·기술·법률 효과)를 실증하고, 부족한 부분은 스크립트·수치·UI로 표현한다.

## 2. 상품군 제안 (확정 목록 아님)

| 분류 | 예시 상품 | 역할 |
|---|---|---|
| 생존·농업 | 곡물, 가축, 목재, 어획물, 소금 | 생활·식량·기본 생산 |
| 원재료 | 철광석, 구리, 석재, 점토, 섬유, 연료용 목탄 | 건설·야금·공예 |
| 수공업 | 철기 도구, 직물, 토기, 목제품, 무기 | 농업생산·군사·도시 소비 |
| 기반·수송 | 선박 부품, 동물 운송 수단, 건축재 | 교역과 대규모 프로젝트 |
| 상류·장거리 교역 | 비단, 향료, 금속 세공품, 기타 고가 교역품 | 지역별 비대칭 교역 수요 |

'현대 산업혁명' 상품인 전기·철도·기관차 등은 이 시대의 경제 경로에서 제거·교체 검토 대상이다. 역사적으로 다른 지역·연대에서 사용된 생산기술은 보편적인 동일 상품체계로 뭉개지지 않게 한다.

## 3. 건물군 제안

- 농경·관개·목축·어업·임업.
- 광산·채석장·목탄·제철·야금.
- 직물·도기·목공·금속공예 작업장.
- 지역 시장·항만·조선·운송 관련 시설.
- 행정·종교·군사 지원 시설.

가능한 한 건물의 입력/출력과 인구의 직업을 연결한다. 예: 농업 생산성 향상 → 농업잉여 확대 → 군사·행정 유지 여력 증가 → 국가 개혁 선택 확대. 단, 이 연쇄를 모두 구현 가능하다고 전제하지 않고 실측한다.

## 4. 기술체계 제안

기술은 실제 7세기 지역별 선후관계를 고증하되, 동일 기술의 세계 동시 해금을 강제하지 않는다.

| 계통 | 예시 주제 | 게임 내 연결 |
|---|---|---|
| 농업·생산 | 관개, 쟁기·경작, 곡물 보관, 야금·철기 가공 | 생산방식·지역 생산성 |
| 도시·교역 | 도량형, 항해·선박 제작, 상업 기록·교역 관행 | 무역·항만·시장 효과 |
| 행정·사회 | 호적, 조세 기록, 행정 문서·교육, 법전·지방 통치 | 조세·관료제·법률 |
| 군사·방어 | 군역 제도, 기병 운용, 성곽·보급 관리 | 병종·비용·전쟁 관련 데이터 |

기술 한 항목은 기술적 발명뿐 아니라 **제도·전파·기술 활용 능력**을 뜻할 수 있다. '철제 농기구' 등 실제로 훨씬 이른 시대부터 존재한 기술을 600년 이후의 세계 보편 최초 발명처럼 표시해서는 안 된다.

## 5. 경제 모델에서 결정할 문제

1. 인구 생계·자급 경제와 시장거래의 경계.
2. 현물세·부역·공납을 경제 모델에서 어떻게 추상화할지.
3. 귀족·종교기관·왕실·상인 등의 경제적 권한을 어떤 소유권·직업으로 표현할지.
4. 먼 지역의 무역과 식량 부족의 관계를 어떻게 시뮬레이션할지.
5. 전쟁과 건설·군사 유지에 들어가는 경제적 부담의 균형.
6. 공업용 자본재 없이 120년 동안 충분한 생산·제도 발전을 제공할 방법.

## 6. 밸런싱 검증 기준 (제안)

- 600년 시작에 어느 국가도 구조적으로 즉시 파산하지 않음(의도된 위기 국가는 이유와 대응 수단 문서화).
- 식량·기본 생활재·군사 물자 부족이 실제 정책 선택을 유발.
- 한 개 생산방식만 연속 선택하는 전략이 절대적인 최선이 되지 않음.
- 국가 확장이 항상 경제적으로 이득이지는 않음.
- 720년에도 국가별 서로 다른 발전 경로와 기술 차이가 유지됨.
- AI가 안정적으로 기본적인 식량·군사·정부 수요를 관리.

수치·트리·건물 이름은 실제 파일을 작성하기 전에 별도 데이터 표로 확정한다.

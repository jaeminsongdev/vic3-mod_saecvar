# 08. 개발 로드맵·품질 검증

- 상태: **개발 단계 제안**, 일정·인력·마일스톤 날짜 확정 아님
- 우선순위: 크게 제작하기 전에 한 번이라도 실제 게임에서 작동하는지를 확인한다.

## Phase 0 — 환경 및 엔진 실증

목표: 기술적으로 불가능한 핵심 가정을 조기에 발견한다.

- 목표 Victoria 3 패치·DLC 의존성 기록.
- 빈 모드 실행 및 로딩·에러 로그 수집.
- 게임 시작 연도를 600년으로, 정규 플레이 구간을 120년으로 설정 가능한지 확인.
- 국가 1~2개, 소수 주에 시작 POP·법률·건물 배치.
- 상품·생산방식·기술 데이터의 변경 최소 예제를 각각 실행.
- 일지·조건부 이벤트, AI·전선·해상 이동의 동작 범위 기록.

**통과 조건:** 시나리오가 안정적으로 시작하고 날짜가 정상 증가하며 테스트 데이터가 의도한 대로 작동. 성공하지 않은 항목은 '구현 가능'이라고 문서화하지 않는다.

## Phase 1 — 한 지역 수직 슬라이스

예시로 동아시아 수–고구려 인접권, 혹은 동로마–사산 국경권 하나를 선정하되, 어느 지역을 먼저 만들지는 **미확정**이다.

- 2~3개 정치체와 주변 주, 핵심 POP·경제 데이터.
- 식량→생산→조세·군대→정치적 변화 루프.
- 15~30년의 조건 기반 일지와 경제 성장·위기.
- 한 국가의 군사형·다른 국가의 행정형 플레이를 비교.

**통과 조건:** 20~30년 동안 AI·플레이어 모두 파국적 결함 없이 선택과 결과의 연결을 확인.

## Phase 2 — 고대 경제·사회 최소 완결

- 시대에 맞지 않는 바닐라 상품·건물·생산방식·기술·법률 정리.
- 경제 및 직업·정치 권력 모델 연결.
- 군사 소비·행정 비용 및 고대 제도 효과 연결.
- 서로 다른 규모의 정치체로 600~720 장기 시험.

**통과 조건:** 120년의 경제 성장·국가 재정·군사 동원·사회 변화가 정상 범위에 있으며, 치명적 게임 정지가 없는 상태.

## Phase 3 — 글로벌 기준선 확장

- 전 세계 600년 정치·인구·경제·문화·종교 데이터를 지역별로 구축.
- 지역별 최소 콘텐츠와 고증·불확실성 표기.
- 역사적인 거리·항로·국가접근성 및 지역별 다른 경제 모델을 점검.
- 대륙별 정치체 밀도와 성능 영향을 검증.

**통과 조건:** 세계에서 시작 가능한 정치체와 지역 데이터에 근본적인 공백이나 시대 착오가 없고, 글로벌 AI 안정성 시험을 통과.

## Phase 4 — 역사적 분기와 차별화 콘텐츠

- 실제 600~720년 사건을 조건부 위기·형성·외교·개혁 콘텐츠로 변환.
- 국가·지역별 장기 개혁 및 문화·종교 콘텐츠.
- AI가 역사적으로 가능한 여러 경로를 선택하는지 확인.
- 같은 시작 설정으로 반복 플레이 결과의 다양성 검토.

**통과 조건:** 역사적 결말을 강제하지 않으면서도 플레이에 반응하는 격변과 상이한 국가 발전 경로가 드러남.

## Phase 5 — 정식 공개 준비

- 한국어/영어 UI·로컬라이제이션 범위 정하기.
- 버전 호환성·에러 로그·게임 중후반 속도·세이브 안정성.
- 플레이어용 설명, 역사적 사실/추정 구분, 알려진 한계 표기.
- 데이터 라이선스와 타 프로젝트의 저작권·모드 자산 재사용 허가 확인.
- 샘플 플레이 3개 이상: 제국, 중견 왕국, 소규모 정치체.

**통과 조건:** 필수 오류 0건, 600~720 테스트 세이브의 중대한 진행 차단 0건, 알려진 결함 문서화.

## 최소 테스트 매트릭스

| 테스트 | 무엇을 확인할까? | 증거 |
|---|---|---|
| 시작 | 600년 게임 로딩·시작 국가 선택 | 로그, 스크린샷 |
| 지속 | 720년 범위에서 연도·세이브·성능 | 세이브, 플레이 로그 |
| 경제 | 식량·필수 생산·건물·시장·정부 재정 | 수치 스냅샷 |
| 정치 | 국가별 법률·계층·급진화·문화·종교 | 상황 비교 |
| 외교 | 전쟁·속국·변경·평화·상업 관계 | 시나리오 로그 |
| 지역 | 각 대륙의 정치·인구·경제 데이터 | 검수 표 |
| AI | 파산·무한 전쟁·무의미한 기술 경로 | 장기 관찰 기록 |
| 회귀 | 게임 패치 및 모드 데이터 변경 후 기존 기능 유지 | 자동/수동 체크리스트 |

## 리뷰·완료 기준

기획·데이터 변경을 '완료'로 판정하기 전 **두 차례 연속 검토에서 수정 필요 항목이 없는지** 확인하는 과정을 권장한다. 자동 스키마 검사와 수동 역사·게임 디자인 검수는 별도로 수행한다.

이 문서는 마일스톤의 순서를 정의할 뿐, 개발 기간·비용을 추정하거나 릴리스 날짜를 약속하지 않는다.
